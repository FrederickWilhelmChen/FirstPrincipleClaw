# FirstPrincipleClaw 下一阶段开发范围

## 目标

把当前本地原型继续推进成真正可接入 OpenClaw 的主线产品，而不是继续堆叠新的概念文档。

## 当前基线

已确认保留：

- OpenClaw 集成是项目主线
- 两层交互是主交互结构
- 深查看面板继续沿用当前本地 Web 方向
- Canvas 只做后续增强，不进入当前主线范围

## 下一阶段必须完成的事情

### 1. OpenClaw 侧适配层

已完成基础骨架，下一步重点变为真实接线和联调：

- 把 hook / plugin 真正接到运行时适配层
- 把 `chat.inject` 真实发进 OpenClaw transcript
- 验证 gateway 配置与会话上下文传递

### 2. 去重与触发规则

基础规则已落到适配层，下一步是端到端验证：

- 首次成功分析可提示
- 复杂度显著上升时可提示
- `can_remove` 集合明显变化时可提示
- 无实质变化、失败、过期状态不提示
- 如需支持“用户显式要求简化”，还需要把该信号接进运行时

### 3. Deep-view 动作闭环

当前页面已补上基本结构，剩余工作是把它和真实会话状态联动起来：

- 接受建议后的持续反馈
- 忽略建议后的持续反馈
- 复制最简方案在目标环境中的可用性
- 与当前 session 的回注或状态同步

### 4. 接入和安装文档

接入说明已创建，剩余工作是实测和收口：

- Windows 接入实测
- macOS 接入实测
- 示例配置校正
- 故障排查补充

## 当前明确不做

- 不再回到“纯独立看板产品”的叙事
- 不再把 React / Flask / WebSocket 作为默认技术路线
- 不把 macOS Canvas 当成首发依赖
- 不继续撰写彼此重复的方案比较文档

## 完成标准

这一阶段完成时，至少应满足：

1. OpenClaw 能触发 FirstClaw 分析
2. OpenClaw transcript 能收到短提示
3. 提示能打开 deep-view 页面
4. deep-view 页面能完成基础动作闭环
5. 整条路径在 Windows 上可成立
