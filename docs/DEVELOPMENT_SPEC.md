# FirstPrincipleClaw 下一阶段开发范围

## 目标

把当前本地原型继续推进成真正可接入 OpenClaw 的主线产品，而不是继续堆叠新的概念文档。

## 当前基线

已确认保留：

- OpenClaw 集成是项目主线
- 两层交互是主交互结构
- 深查看面板继续沿用当前本地 Web 方向
- Canvas 只做后续增强，不进入当前主线范围

## 下一阶段必须完成的事情

### 1. OpenClaw 侧适配层

补齐以下运行时代码或配置：

- bootstrap 注入内容
- hook / plugin 触发时机
- 从分析结果组装 prompt payload
- `chat.inject` 发送逻辑

### 2. 去重与触发规则

把已有文档里的规则落到代码：

- 首次成功分析可提示
- 复杂度显著上升时可提示
- `can_remove` 集合明显变化时可提示
- 用户显式要求简化时可提示
- 无实质变化、失败、过期状态不提示

### 3. Deep-view 动作闭环

把当前页面补全为真正可用的深查看页：

- 显示当前状态
- 解释为什么收到这条提示
- 接受建议
- 忽略建议
- 复制最简方案

### 4. 接入和安装文档

补齐真正可执行的接入说明：

- Windows 接入
- macOS 接入
- 示例配置
- 故障排查

## 当前明确不做

- 不再回到“纯独立看板产品”的叙事
- 不再把 React / Flask / WebSocket 作为默认技术路线
- 不把 macOS Canvas 当成首发依赖
- 不继续撰写彼此重复的方案比较文档

## 完成标准

这一阶段完成时，至少应满足：

1. OpenClaw 能触发 FirstClaw 分析
2. OpenClaw transcript 能收到短提示
3. 提示能打开 deep-view 页面
4. deep-view 页面能完成基础动作闭环
5. 整条路径在 Windows 上可成立
